Local stream diagnostic follow-up: the `destination stream closed early` message was isolated to the attendance E2E flow, which saves successfully, calls `router.refresh()`, and previously let Playwright tear down immediately after the optimistic success toast. React's bundled RSC renderer binds this message to the destination stream's `close` event and aborts that render request; it is a cancellation path, not an unhandled rejection or a write-after-close. Waiting for the refreshed server-rendered attendance record avoids closing the page before the updated record reaches the UI. `response.finished()` was unsuitable because the RSC response body remained pending past the 30-second test timeout. After replacing that wait with the rendered-record assertion, two consecutive `pnpm test:ci` runs passed all 47 parallel E2E tests and neither run emitted the destination-close diagnostic. This is local Windows evidence only; the hosted CI gate remains OPEN.

The CI type-regeneration step has not been verified locally. `supabase gen types --local` failed with a local container error when `postgres-meta` was excluded; including it on this Windows Docker host failed its health check. The CI database job now starts `postgres-meta` and the required Supabase services for this step, excluding only Studio. The local failure does not establish whether the GitHub runner will pass it.

## Top release risks

1. **Credential exposure:** a secret-style Supabase credential was pasted into conversation context. Rotate it and verify repository/history/client-bundle exposure before release.
2. **Migration drift:** the owner-provided prior push transcript covers migrations only through `20260929024205`; four later migrations are pending or unverified.
3. **Authorization defects:** role/RLS changes span payments, attendance, assessments, materials, certificates, reports, and admin MFA. Staging tests are still required.
4. **Financial correctness:** confirm GST tax split/rounding, invoice identity and number policy, void/credit-note accounting, and migration treatment with the finance owner.
5. **Legal identity:** confirm the legal entity name, GSTIN, invoice address, certificate signatory, brand/verification domain, and software license rights.
6. **Restore uncertainty:** backups/PITR and restore duration have not been proven in a scratch project.
7. **Unknown scale:** no measured response percentiles, target-volume explain plans, dashboard LCP, or concurrency run exists.
8. **Incomplete browser evidence:** authenticated E2E is still missing student import, trainer assignment, certificate revoke/reissue/batch issue, and credit-note flows. The current release tree has no student CSV import or credit-note workflow and no certificate revoke/reissue API; implementation is required before the requested browser evidence can exist.
9. **Monitoring gap:** Sentry ingestion, source maps, paging destination, and alert acknowledgement are not confirmed.
10. **Visual/accessibility gap:** axe automation does not prove Lighthouse ≥95, manual WCAG 2.2 AA conformance, or correct printed font embedding/layout.
