# Alert rules and ownership

The operations owner is the primary responder; the application maintainer is the technical backup. Route SEV-1 alerts to both. Configure these conditions in Vercel Observability, Sentry, and Supabase/Grafana as appropriate; repository code emits request logs and product events but cannot provision provider alert rules.

| Signal                      | Trigger                                                                                                             | Source                                           | Owner / first action                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Application 5xx             | More than 2% of requests return 5xx over 5 minutes, with at least 20 requests                                       | Vercel request metrics; Sentry issues            | App maintainer: compare release SHA, request IDs, `/api/ready`; rollback application if release regression.              |
| API p95 latency             | p95 exceeds 800 ms for 10 minutes; page immediately if above 2 seconds for 5 minutes                                | Vercel Observability                             | App maintainer: group by route and release, inspect Supabase query/connection load.                                      |
| Failed payment transactions | At least 3 `payment_failed` events in 5 minutes, or any confirmed partial-write/data-integrity failure              | Vercel structured logs and Sentry errors         | Operations owner + app maintainer: check idempotency key outcomes and atomic RPC/database health.                        |
| Authentication failures     | At least 15 `login_failed` events from one IP in 5 minutes, or 50 across the app in 5 minutes                       | Vercel structured logs/log drain                 | Operations owner: check Auth logs, rate-limit health, and credential-stuffing signs. Never log submitted credentials.    |
| Database connections        | Connections exceed 80% of the configured project limit for 5 minutes                                                | Supabase Metrics API / dashboard                 | App maintainer: inspect pooler use and long-running queries; scale only with the project owner.                          |
| Storage errors              | At least 3 `storage_error` events in 5 minutes                                                                      | Vercel structured logs and Supabase Storage logs | App maintainer: inspect Storage service health and bucket policies.                                                      |
| Verification throttling     | More than 20 `verification_rate_limited` events in 5 minutes                                                        | Vercel structured logs                           | Operations owner: check distribution and proxy IP forwarding; retain existing abuse controls.                            |
| Backups/PITR                | Missing expected daily backup, latest recoverable point older than the declared RPO, or PITR disabled when required | Supabase Dashboard; scheduled manual checklist   | Operations owner: restore backup coverage and update recovery-point record.                                              |
| Scheduled jobs              | Any production cron/backup job failure or missed expected run                                                       | Provider job history and alert destination       | Operations owner: identify job owner, rerun safely, verify idempotency. No application-owned cron is currently declared. |
| Uptime                      | `/api/ready` fails twice in a row or `/login` is not HTTP 200 from two regions                                      | External uptime monitor                          | Operations owner: check Vercel status and `/api/ready`; notify app maintainer on repeated failures.                      |

Do not mark an alert active until the provider destination, primary contact, and backup contact have acknowledged a test notification. The alert rules above are thresholds to configure, not evidence that external alerts are already active.

Configure an external monitor to request `https://<app-domain>/api/ready` every minute and `https://<app-domain>/login` at least every five minutes. `/api/ready` is rate-limited to 30 requests/minute per source IP; use one monitor per region or coordinate the polling interval. Route notifications to the operations owner and application maintainer. A public status page is optional.
